# ZIP

zip压缩包主要由三大部分组成：**文件数据区 中央目录记录区/核心目录记录 中央目录记录尾部区**  
注意zip压缩包是小端序存储的 关于端序在week1写png的时候提过 这里就不解释了

## 文件数据区

由一系列本地文件记录组成 主要记录了压缩前后文件的元数据以及压缩后的文件  
由 **本地文件头、文件数据、文件描述** 三部分组成

**本地文件头**

主要是压缩文件的元数据

| 内容                   | 字节数 | 说明                                                      |
| :--------------------- | :----- | :-------------------------------------------------------- |
| 文件头标识             | 4      | `50 4B 03 04`                                             |
| 最低支持的ZIP规范版本  | 2      | apk压缩版本默认是20（实际版本需÷10，如20÷10=2.0）         |
| 通用标志位(伪加密要用) | 2      | 标识文件是否有加密 是否有数据描述部分                     |
| 压缩方式               | 2      | apk压缩默认是Deflate，传8；0表示不压缩                    |
| 文件最后修改时间       | 2      | MS-DOS格式编码的时间                                      |
| 文件最后修改日期       | 2      | MS-DOS格式编码的日期                                      |
| CRC-32校验码           | 4      | 文件未压缩时的CRC-32校验码，若通用标志位第3位为1则此处为0 |
| 压缩后大小             | 4      | 文件压缩后的大小，若通用标志位第3位为1则此处为0           |
| 未压缩大小             | 4      | 文件未压缩的大小，若通用标志位第3位为1则此处为0           |
| 文件名长度             | 2      | 记录文件名的长度（假设为n）                               |
| 扩展区长度             | 2      | 记录扩展区的长度（假设为m）                               |
| 文件名                 | n      | 记录文件名                                                |
| 扩展数据               | m      | 记录扩展数据                                              |

- 版本定义补充

```
当前最低功能版本定义如下：（压缩包记录的解压版本都是需要版本*10，比如：2.0 * 10 = 20）
1.0 –> 默认值
1.1 –> 文件是卷标
2.0 –> 文件是一个文件夹（目录）
2.0 –> 使用 Deflate 压缩来压缩文件
2.0 –> 使用传统的 PKWARE 加密对文件进行加密
2.1 –> 使用 Deflate64™ 压缩文件
2.5 –> 使用 PKWARE DCL Implode 压缩文件
2.7 –> 文件是补丁数据集
4.5 –> 文件使用 ZIP64 格式扩展
4.6 –> 使用 BZIP2 压缩文件压缩
5.0 –> 文件使用 DES 加密
5.0 –> 文件使用 3DES 加密
5.0 –> 使用原始 RC2 加密对文件进行加密
5.0 –> 使用 RC4 加密对文件进行加密
5.1 –> 文件使用 AES 加密进行加密
5.1 –> 使用更正的 RC2 加密对文件进行加密
5.2 –> 使用更正的 RC2-64 加密对文件进行加密
6.1 –> 使用非 OAEP 密钥包装对文件进行加密
6.2 –> 中央目录加密
```

- 用标志位补充

总共两个字节 小端序存储 假设十六进制显示为 `00 00`，还原为二进制是 `00000000 00000000`（注意低位字节在前）。

第 0 位为 1（二进制 `xxxxxxxx xxxxxxx1`） 表示文件已加密  
因为第 0 位对应最低位，所以**第一个字节为奇数时，第 0 位必为 1** 即文件被加密。例如 `09 00` 的第一个字节 `09` 是奇数，所以它代表加密

第 3 位为 1（二进制 `xxxxxxxx xxxxx1xx`） 表示存在数据描述部分  
此时本地文件头中的 CRC-32、压缩大小、未压缩大小字段都会被置为0 真实值放在压缩数据之后的数据描述部分

> apk 默认传 0，也有传 2048、2056 的情况。

- 压缩方式补充

现在基本都是 Deflated 不过还是列一列吧

```
0  –> 不压缩（Stored）
1  –> Shrunk 压缩
2  –> Reduced 压缩因子1
3  –> Reduced 压缩因子2
4  –> Reduced 压缩因子3
5  –> Reduced 压缩因子4
6  –> Imploded 压缩
7  –> Reserved 保留（曾计划用于 Tokenizing 算法，从未正式发布）
8  –> Deflated 压缩
9  –> Deflate64™ 压缩
10 –> Imploding 压缩
11 –> Reserved 保留
12 –> BZIP2 压缩
```

**文件数据：**

紧跟在本地文件头之后 一般是压缩后的文件数据或不压缩时的原始文件数据

**文件描述：**

不一定有 因为刚开始没有这个规范 后面才加上去的  
仅在通用位标志第3位为1时才存在 紧跟在文件数据之后  
正常情况下不需要使用 只有无法在文件中查找时才使用此描述符

## 中央目录记录区

由一系列中央目录记录组成 一条中央目录记录对应数据区中的一个压缩文件记录

**中央目录记录**

| 内容                   | 字节数 | 说明                                                 |
| :--------------------- | :----- | :--------------------------------------------------- |
| 文件头标识             | 4      | `50 4B 01 02`                                        |
| 压缩所用的版本         | 2      | 同本地文件头 最低支持版本，apk默认20                 |
| 解压所需的最小版本     | 2      | 同本地文件头 最低支持版本，apk默认20                 |
| 通用标志位(伪加密要用) | 2      | 同本地文件头 通用标志位                              |
| 压缩方式               | 2      | 同本地文件头 压缩方式                                |
| 文件最后修改时间       | 2      | 同本地文件头 MS-DOS格式编码的时间                    |
| 文件最后修改日期       | 2      | 同本地文件头 MS-DOS格式编码的日期                    |
| CRC-32校验码           | 4      | 同本地文件头 文件未压缩时的CRC-32校验码              |
| 压缩后大小             | 4      | 同本地文件头 文件压缩后的大小                        |
| 未压缩大小             | 4      | 同本地文件头 文件未压缩的大小                        |
| 文件名长度             | 2      | 同本地文件头 记录文件名的长度（假设为n）             |
| 扩展区长度             | 2      | 同本地文件头 记录扩展区的长度（假设为m）             |
| 文件注释长度           | 2      | 记录文件注释的长度（假设为k）                        |
| 磁盘编号               | 2      | 文件开始位置的磁盘编号，一般传0                      |
| 内部文件属性           | 2      | 一般传0                                              |
| 外部文件属性           | 4      | 一般传0                                              |
| 本地文件头偏移量       | 4      | 记录对应数据区本地文件头相对于压缩包开始位置的偏移量 |
| 文件名                 | n      | 同本地文件头 记录文件名                              |
| 扩展数据               | m      | 同本地文件头 记录扩展数据                            |
| 文件注释               | k      | 记录文件注释                                         |

## 中央目录记录尾部区

主要用来定位中央目录记录区的开始位置 同时记录压缩包的注释内容

| 内容                 | 字节数 | 说明                                       |
| :------------------- | :----- | :----------------------------------------- |
| 文件头标识           | 4      | `50 4B 05 06`                              |
| 当前磁盘编号         | 2      | 中央目录记录尾部区所在磁盘编号             |
| 中央目录起始磁盘编号 | 2      | 中央目录开始位置所在的磁盘编号             |
| 当前磁盘核心目录数量 | 2      | 该磁盘上所记录的核心目录数量               |
| 文件总数             | 2      | zip压缩包中的文件总数                      |
| 中央目录大小         | 4      | 整个中央目录的大小（以字节为单位）         |
| 中央目录起始偏移     | 4      | 中央目录开始位置相对于压缩包起始的相对位移 |
| 注释长度             | 2      | 注释内容的长度（假设为n）                  |
| 注释内容             | n      | 记录注释内容                               |
