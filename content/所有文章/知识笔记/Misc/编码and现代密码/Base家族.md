# Base家族

Base编码是一种将二进制数据转换为可打印字符的编码方式  
确保数据在只能处理文本的通道（如邮件、URL）中能完好无损地传输

原理是 **把原数据转换为二进制串 再分组 最后按表映射成字符**  
如果原始数据最后不够分组，会用特殊字符（比如=）来填充

Base`N` 的 `N` 即为字符集的大小  
注意 Base编码的字符集是有顺序的 也是可以被篡改顺序和内容的

> 后半段的编码要不位数不固定 要不量太大 所以不放映射表了

### Base 16

base16编码也称为十六进制编码或Hex编码  
按4为分组 字符集为 0-9 A-F

由于4bit就可以表示 $2^4 = 16$ 个字符  
所以用4bit可以表示所有的十六进制数 (base16编码用小端模式存储)  
编码后长度是明文的恰好两倍

编码过程为 按4个一组切分二进制数据 再按下表映射  
(若二进制数据不是4的倍数 则在后方补0)

```
0000 -> 0
0001 -> 1
0010 -> 2
0011 -> 3
0100 -> 4
0101 -> 5
0110 -> 6
0111 -> 7
1000 -> 8
1001 -> 9
1010 -> A
1011 -> B
1100 -> C
1101 -> D
1110 -> E
1111 -> F
```

### Base32

按5位分组 字符集为 2-7 A-Z

编码原理和 bases16 基本相同 只不过变成了5个二进制数一组  
Base32编码通常用于需要在文本环境中表示二进制数据的场景  
例如电子邮件中的附件编码、URL中的参数传递等  
$2^5 = 32$ 表如下

(若二进制数据不是5的倍数 则在后方补0 并用=填充)

```
00000 -> A
00001 -> B
00010 -> C
00011 -> D
00100 -> E
00101 -> F
00110 -> G
00111 -> H
01000 -> I
01001 -> J
01010 -> K
01011 -> L
01100 -> M
01101 -> N
01110 -> O
01111 -> P
10000 -> Q
10001 -> R
10010 -> S
10011 -> T
10100 -> U
10101 -> V
10110 -> W
10111 -> X
11000 -> Y
11001 -> Z
11010 -> 2
11011 -> 3
11100 -> 4
11101 -> 5
11110 -> 6
11111 -> 7
```

### Base36

分组位数不固定 字符集为 0-9 A-z

### Base58

分组位数不固定

Base58字符集通常包括58个字符 通常是由除去Base62中易混淆的字符  
如 `0` `O` `I` 和 `l` 以及可能引起歧义的字符 如 `+` 和 `/`

通常用于表示加密货币地址和其他数据

### Base62

分组位数不固定 字符集为 0-9 A-Z a-z

### Base64

按6位分组 字符集为 0-9 A-Z a-z + /

### Base85

按32位分组 字符集

```
0-9 a-z A-Z
!"#$%&'()*+,-.:;<=>?@[\]^_`
```

### Base91

按 13/14 位分组

字符集

```
0-9 a-z A-Z
!"#$%&()*+,./:;<=>?@[]^_`{|}~
```

### Base92

字符集不确定 Base92 没有统一标准  
常见的一种是比 Base91 增加一个 ~ 符号 也就是

```
0-9 a-z A-Z
!#$%& ()*+,./:;<=>?@ []^_` {|}”~
```

### Base100

Base100 使用 256 个Emoji 作为字母表
